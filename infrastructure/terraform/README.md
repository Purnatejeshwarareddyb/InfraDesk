# Terraform: InfraDesk Docker resources

Terraform describes the Docker objects of a **second, independent copy** of InfraDesk and creates
them with one command. It does not touch the Docker Compose stack.

| | Docker Compose | Terraform (this folder) |
|---|---|---|
| Network | `infradesk-net` | `infradesk-tf-net` |
| Volume | `infradesk-data` | `infradesk-tf-data` |
| Containers | `infradesk-backend-1`, `infradesk-frontend-1` | `infradesk-tf-backend`, `infradesk-tf-web` |
| Host port | `${INFRADESK_PORT}` (8080) | `web_port` (**8081**) |

Provider: `kreuzwerker/docker`, constraint `~> 3.0`. Images are **not** built by Terraform; it uses the
same tags that `docker build` / Compose produce (`infradesk-backend:latest`, `infradesk-frontend:latest`).

## NOT RUN in the environment where this was written

`terraform` could not be downloaded there (the network refused it), so `terraform fmt`, `init`,
`validate`, `plan` and `apply` were **never executed** and **no `.terraform.lock.hcl` exists** (it must
be generated by `terraform init`, not written by hand). Run these on your laptop:

```bash
cd infrastructure/terraform
terraform fmt -check -recursive      # good: prints nothing, exit code 0
terraform init                       # good: "Terraform has been successfully initialized!"; creates .terraform.lock.hcl
terraform validate                   # good: "Success! The configuration is valid."
```

After `init` succeeds, **commit `.terraform.lock.hcl`** (it pins the exact provider build; `.gitignore`
already allows it). If `terraform fmt` rewrites a file, commit the result.

## Deploy

```bash
# 1. Build the images once (from the repository root)
docker build -f docker/backend.Dockerfile  -t infradesk-backend:latest .
docker build -f docker/frontend.Dockerfile -t infradesk-frontend:latest .

# 2. Provide the secret (never write it into a committed file)
export TF_VAR_secret_key="$(python3 -c 'import secrets; print(secrets.token_urlsafe(48))')"
cp terraform.tfvars.example terraform.tfvars   # optional: change ports/images

# 3. Plan and apply
terraform plan
terraform apply          # type "yes"; waits until both healthchecks pass
terraform output url     # http://localhost:8081
```

The secret ends up in `terraform.tfstate` in clear text (Terraform limitation). The state file is
git-ignored; keep it on your own machine and do not share it.

Windows with native Terraform and Docker Desktop: set `docker_host = "npipe:////./pipe/docker_engine"`.
Inside WSL2 with Docker Desktop integration the default socket works.

## Two deployment modes and who owns what

* **Mode A - Terraform alone.** Terraform creates network, volume and both containers. It owns all
  four resources.
* **Mode B - Terraform for infrastructure, Ansible for the application.** Terraform creates network,
  volume and (optionally) containers; Ansible only handles app files, image builds and checks. Use
  `manage_data_volume = false` if the volume should live outside Terraform.

Boundary (see also `infrastructure/puppet/README.md`):

| Layer | Tool | Owns |
|---|---|---|
| Host baseline (packages, user, `/opt/infradesk`, `/etc/infradesk`, docker service, backup timer) | Puppet | nothing in Docker |
| Application deployment (Compose project `infradesk`, files in `/opt/infradesk/app`) | Ansible | Compose resources |
| `infradesk-tf-*` Docker resources | Terraform | only these |

Terraform never uses the names `infradesk-net`, `infradesk-data`, or Compose container names.

## Safe destroy and the data volume

`make tf-destroy` removes only the **containers and the network** and keeps the volume:

```bash
terraform destroy -target=docker_container.web -target=docker_container.backend -target=docker_network.net
```

To delete **everything including the database**, you must do it on purpose:

```bash
terraform destroy          # destroys the volume too when manage_data_volume = true
```

To make a full `terraform destroy` unable to delete data, set `manage_data_volume = false` and create
the volume yourself once (`docker volume create infradesk-tf-data`); Terraform then only mounts it.
Alternative for an existing deployment: `terraform state rm 'docker_volume.data[0]'` (forget the
volume; Docker keeps it). Check what remains with `docker volume ls | grep infradesk-tf`.

## Provider caching for offline use

`terraform init` downloads the provider from the internet once. To work offline afterwards:

```bash
# Option 1: a shared plugin cache directory (add to ~/.terraformrc or %APPDATA%\terraform.rc)
#   plugin_cache_dir = "$HOME/.terraform.d/plugin-cache"
mkdir -p ~/.terraform.d/plugin-cache
export TF_PLUGIN_CACHE_DIR=~/.terraform.d/plugin-cache
terraform init                      # online, once: fills the cache

# Option 2: a local filesystem mirror (copy it to the offline machine)
terraform providers mirror ./provider-mirror
# on the offline machine, in ~/.terraformrc:
#   provider_installation {
#     filesystem_mirror { path = "/path/to/provider-mirror" }
#     direct { exclude = ["registry.terraform.io/*/*"] }
#   }
terraform init
```

`scripts/offline_preload.sh --terraform` runs option 2 into `.offline/provider-mirror` when Terraform is installed.
